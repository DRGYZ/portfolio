A desktop companion that responds to context, not just prompts.

MIKO explores a quieter kind of computing: a local-first character that notices

02 — PRESENCE / PREMISE + PROOF
============================================================

Core premise

DESIGNED FOR THE PERIPHERY.

Most assistants wait for a command. MIKO stays quietly present, then expresses
only what the moment earns.

01 · Continuous
Lightweight local signals give the companion situational awareness without
turning every moment into a conversation.

02 · Restrained
Posture, timing, and short reactions create presence without competing with the

============================================================
03 — PERSONALITY
============================================================

A COMPANION HAS MOODS.

MIKO's personality lives in hand-authored pixel animation. Each posture is a
readable response to desktop context—not a generic avatar skin.

Context can influence a mood; explicit user and internal companion states can
too. The character remains authored, not generated on demand.

01 · Coding / focus
A code editor or terminal becomes the active workspace.
“checking the logic”

02 · Listening / rhythm
A background music session remains audible.
“tiny concert mode”

03 · Watching / attention
Video playback takes focus in a browser or local player.
“I am watching too”

04 · Annoyed / disruption
MIKO is relocated away from the primary display.
“bring me back”

Secondary moods:
- Curious / exploration — Research, documentation, or exploratory browsing.
  “what are we reading?”
- Sleepy / standby — User inactivity passes the configured idle threshold.
  “still here”
- Celebrating / reward — An explicit positive or achievement state is triggered.
  “proud mode!”

Movement atlas · 100 frames

A BODY FOR THE DESKTOP.

Walking, jumping, waving, crouching, and relocation tantrums let MIKO occupy the
edge of the screen like a small physical presence.

============================================================
05 — LOCAL-FIRST / BOUNDARIES
============================================================

DESIGNED FOR YOUR MACHINE.

Local core
The WPF shell and Python sidecar communicate over local loopback. There is no
built-in remote telemetry.

Clear limits
Titles, processes, media state, and idle time are read in memory. Keystrokes,
clipboard, and file contents are excluded.

User choice
Optional model features are off by default and follow the endpoint configured by
the user, such as local Ollama.

Current boundaries:
- Windows-specific Win32 and WPF runtime
- Heuristic-first classification and local loopback IPC
- Lightweight foreground polling rather than persistent capture

Exploring next:
- Standalone packaging and simpler setup
- Multi-monitor and high-DPI validation
- Sidecar refactoring and local voice tuning

MIKO is an active experimental project. This case study documents the working
prototype as it exists today; architecture, interaction rules, and packaging may
continue to evolve.
